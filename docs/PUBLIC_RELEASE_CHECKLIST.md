# Public Release Checklist

The code repository is assembled and testable independently of private paths.
Before making it public, the maintainers should confirm:

- [ ] Final GitHub organization, repository name, and maintainer contacts.
- [ ] Author order and software citation in `CITATION.cff`.
- [ ] Whether the manuscript source or preprint PDF should be included or linked.
- [ ] Public URLs, accession identifiers, and licenses for every benchmark.
- [ ] Public access instructions for the EPT source, checkpoint, nvMolKit, and
      covariance-only whitener.
- [ ] Whether frozen aggregate result tables should be released as lightweight
      artifacts.
- [ ] Paper DOI or preprint identifier after assignment.
- [ ] Independent reproduction of parameter selection and all reported tables.
- [ ] Repository secret scan and dependency/license review.
- [ ] Legal review of the custom commercial-notice license and contributor terms.
- [ ] Version tag and archived release (for example, Zenodo) used by the paper.
